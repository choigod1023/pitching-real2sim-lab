# 다른 투구에서도 같은 수정안이 적용되는가

2026-10-30. **기존 +0.647km/h 후보를 다른 8구에 적용했지만, 사전 힘·일·자세 기준을 통과한 투구는 없었다.** 같은 선수의 나머지 4구에서 별도로 재탐색했을 때도 이번 계산 예산 안에서는 합격 후보를 찾지 못했다. 원래 한 투구의 조건부 결과를 반복 가능한 선수 능력 향상으로 해석할 수 없다.

이 문서는 생체역학 연구용 계산 기록이며 훈련·의료 조언이 아니다. 실제 구속 향상, 부상 위험 감소, 편안함을 확인한 연구가 아니다.

## 계산 전에 고정한 내용

[PROTOCOL.md](PROTOCOL.md)를 `01e0d06`에서 먼저 커밋했다. PR135의 원본 압축 보고서 해시를 검증한 뒤 33계수를 그대로 읽었다. 비교 대상은 같은 선수 user2의 3034_2~5, 숫자 ID 순 다음 우투수 user72와 user90의 사전식 첫 두 투구다. 세 선수 모두 기존 개발 자료에 포함된 적이 있으므로 독립 외부 검증이라고 부르지 않는다.

손/전완 20Hz 처리, 제공 관절 중심, FP10~BR, 일반 관성, 15cm 그립을 유지했다. 구속 기록으로 그립·이탈 시각·관성·관절 범위·힘 한도를 고르지 않았다. 같은 선수는 기준 첫 투구의 분절 길이를 고정했으며, 각 투구의 기준 힘은 그 기하에서 다시 계산했다. 매 투구의 원래 길이와 차이는 결과 ledger에 남겼다. user2의 길이 차이는 상완 약 -7.51~0mm, 전완 0~+7.11mm였다. 이를 새 골 길이 정답이나 선수 자세 교정량으로 해석하지 않는다.

## 고정 전이: 수치가 양수여도 제약을 넘으면 실패

주 분석은 원래 계수와 마지막 60ms 시간 기저를 그대로 쓰되, 각 수신 투구의 입력 최대값 2%를 척도로 삼는 **정규화된 입력 규칙**이다. 동일한 절대 토크나 동일한 관절 각도 처방이 아니다. 아래 값은 dt/2의 실제 RK4 적분 결과다.

보조 분석에서는 원래 투구의 **실제 절대 입력 차이**를 BR 상대 시각으로 보간하고 수신 투구 입력 한도로 투영했다. 이 방식도 같은 선수 0/4, 다른 선수 0/4다. 같은 선수의 변화는 각각 +0.686, +0.484, +0.617, +0.506km/h, 다른 선수는 +0.719, +0.847, +0.605, +0.791km/h였지만 모두 최종 실패했다. 보간·clipping 내역과 두 해상도 결과도 보존했다.

### 무엇이 실패했는가

3034_2의 정규화 전이는 어깨 회전 순 일이 **+0.856758J**, 해당 회전 좌표 양의 일이 **+0.646490J** 늘었다. 팔 전체 성분별 양의 일 합은 오히려 감소했지만 일부 좌표의 비용은 증가했다. 전체 합만 보면 놓치는 실패다.

3034_3의 최대 회전 차이는 **4.398°**로 사전 3° 한도를 넘었다. 다른 선수의 정규화 전이는 최대 회전 차이가 **6.095~7.313°**였다. 원래 투구에서의 작은 수정 규칙이 다른 초기 자세와 속도에서도 작은 자세 차이를 만든다고 가정할 수 없다. 모든 수치·위반 좌표는 [results/summary.json](results/summary.json)에 있다.

## 같은 선수의 투구별 재탐색

고정 전이와 별도로 3034_2~5에서 두 시작점(0, 원래 계수), 시작점당 120개 두 해상도 계산 쌍을 평가했다. 총 **960쌍 = 1,920회 후보 적분**이며, 기준·전이·독립 재생 계산은 별도다. 4구 모두 240쌍의 계산 예산에 도달했고 최적화 수렴은 확인하지 못했다.

전체 A gate, 자세, 양의 구속 차이, 해상도 조건을 함께 통과한 수정은 0개였다. 각 투구에서 선택된 결과는 **입력 수정 0, 구속 변화 0km/h인 원래 기준 fallback**이다. 일부 실패 후보의 구속 변화가 더 컸어도 채택하지 않았다. 이 결과는 이번 방법과 계산 예산의 한계이지, 허용 가능한 모든 수정안이 없다는 증명이 아니다.

## 원래 +0.647의 한계도 유지한다

원래 3034_1 후보는 기존 A gate를 재현했다. 그러나 전체 순 일이 **+1.124670J**, root 힘 벡터 최대값이 **+0.010509N** 증가했고 별도 B 검사는 실패했다. A는 이 두 물리량을 전부 제한하는 기준이 아니다. 따라서 원래 결과도 “모든 힘과 일을 늘리지 않는 후보”가 아니다.

같은 초기 상태와 저장된 입력에서 모든 고정 전이·선택 결과를 독립 재적분해 상태를 비트 단위로 대조하고 accounting을 재계산했다. 이는 코드와 수치의 검산이며, 실제 반사실적 구속 오차나 생리학적 능력 검증이 아니다. 기존 약 16.7km/h의 기준 모델 차이를 해결한 결과도 아니다. 실제 효과의 95% 구간, 근육 능력, 해부학적 관절축, 손가락/공 접촉과 이탈, 구위·제구 효과는 여전히 미검증이다.

통과한 새 수정 후보가 없으므로 **새 향상 영상은 만들지 않았다.** 원래 영상에 다른 투구의 숫자를 대입하지 않았다. `render.py`는 같은 투구의 저장된 실제 적분 상태와 합격 판정을 확인한 뒤에만 원래/수정 팔·손·공 영상을 만들도록 구현했고, 원래 투구·실패·0변화 결과의 향상 영상 출력을 거부한다.

## 다음 연구에서 바꿀 것

1. **한 투구의 최고 구속을 최적화하는 문제에서, 여러 투구에서 함께 성립하는 수정 규칙을 찾는 문제로 바꾼다.** 같은 선수의 학습 투구들에서 힘/일/자세를 동시에 제한하고, 사용하지 않은 투구를 마지막 평가로 남긴다. 이번에 이미 본 8구를 새 미사용 자료라고 재분류하지 않는다.
2. 전체 순 일과 root 힘 벡터 최대값까지 포함하는 새 연구 기준을 별도 사전 등록한다. 기존 A의 성공을 새 기준 성공으로 바꾸지 않는다. 축별 일, 그룹별 일, 근육 능력은 서로 다르므로 이름만 바꾸어 혼용하지 않는다.
3. 입력 계수가 어떤 관절 위치/각도/타이밍 차이를 만드는지 확인하고, 선수에게 설명할 수 있는 해부학적 축으로 대응시키기 전에는 동작 처방을 만들지 않는다. 피니시 구간의 에너지 흡수 부담도 검사해야 한다.
4. 수정 투구의 실제 공/손 이탈 관측 없이 오차 범위 밖의 실제 효과라고 판단하지 않는다. 구위에는 회전수·3D축·궤적, 제구에는 의도 목표와 도착점 분산이 필요하다. 이번 실험은 이를 추가 측정하지 않았다.

## 실행과 검증

저장소 루트에서 `../.venv/Scripts/python.exe`를 사용했다. 실제 실행 명령은 다음과 같다. 각 작업의 출력은 투구별 폴더로 격리했다.

```powershell
python -m unittest coach_hypotheses.pitch_transfer.test_study coach_hypotheses.pitch_transfer.test_report -q
python -m coach_hypotheses.pitch_transfer.study --lab .. --out artifacts/pitch-transfer --pitch 3034_1
# 같은 명령으로 2996_1, 2996_2, 3044_1, 3044_2를 실행
python -m coach_hypotheses.pitch_transfer.study --lab .. --out artifacts/pitch-transfer --pitch 3034_2 --refit
# 같은 명령으로 3034_3, 3034_4, 3034_5를 실행
python -m coach_hypotheses.pitch_transfer.report --source artifacts/pitch-transfer --out coach_hypotheses/pitch_transfer/results
# 전체 테스트는 unittest.defaultTestLoader.discover('.')로 실행하고 이전 오류 ID와 비교
```

새 테스트 **15/15 통과**. 전체 **479개 중 467 통과, 기존 오류 10개, skip 2개, assertion failure 0개, 새 오류 0개**다. 기존 오류는 opensim 모듈 부재 9개, 로컬 formula_checks.json 부재 1개다. 상세 ID는 [results/suite_verification.json](results/suite_verification.json)에 있다. 코드 테스트 통과를 연구 gate 통과로 바꾸지 않았으며 전역 연구 gate도 진전시키지 않았다.

`results/*.json.gz`는 모든 투구의 원래 결과·실패·최적화 중간 기록을 무손실 보존한다. 압축 전후 SHA256은 summary의 archives에 기록했다. 로컬 원시 데이터/NPZ는 Git에 올리지 않았다. 계산 산출물과 데이터 유래 결과는 CC BY-NC-SA 4.0 조건을 따른다.
