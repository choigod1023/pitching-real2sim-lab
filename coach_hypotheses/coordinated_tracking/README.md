# 기준 자세를 유지하는 협응 제어: 실행 결과

2026-10-30. 사용자의 질문에 답하면, 현재 구속 증가량은 **실제 오차범위 안으로 판정돼 무효인 것이 아니라, 실제 개입 효과의 오차범위 자체가 미확인**이다. 시뮬레이션 내부의 증가량은 수치적으로 재현되지만 기존 힘·일 또는 자세 제한을 만족하지 못했다. 모델의 절대 구속 MAE나 다른 개발 투구의 잔차를 개입 효과의95%구간으로 대입하지 않는다.

이번에는 이전의 전체 입력 차단 보호기를 반복하지 않고, 기준 실제 RK4 궤적을 유지하도록 어깨–팔꿈치–전완–손목의 일반화 입력을 함께 조정하는 제어를 구현했다. 모델의 마커 축·일반 관성·자유 어깨 외력은 그대로이며 실제 근육/해부학 제어로 검증한 것이 아니다. 실제 선수의 성능·안전·편안함·훈련 효과를 입증하지 않는다.

## 사전 고정과 구현

[PROTOCOL.md](PROTOCOL.md)를 commit `5f22b8e`에서 결과 실행 전에 고정했다. 같은3034_1, 그립15cm, 공칭이탈시각, 초기 상태와 기존 예산을 유지했다. 마지막30ms에서 마커 손목Z축0.5/1/2°를 cubic-in/smootherstep으로 수정하고, feedforward-only 또는5/10/20Hz의 공학적 feedback gain을 적용했다. 총24조건×두 해상도로48개 후보 실행을 수행했다. 레이더 구속은 선택·적합에 사용하지 않았다.

입력은 기준 실제 입력, 목표/기준의 역동역학 차이, 질량행렬을 반영한 위치·속도 피드백의 합이다. 모든DOF를 기존 성분peak·관절3축 노름peak로 제한했다. 실제 속도로 계산한 양/음의 일·어깨 병진/회전순일은 기존gate로 따로 검사했다. 최대회전3°·공중심20mm·방출방향1°·두해상도 판정도 유지했다.

`controller.py`는 목표상태·역동역학 차이·입력 제한·질량행렬 feedback·실제RK4·결과판정을 제공한다. `test_controller.py`는 quaternion 목표, terminal 입력 제외, 질량행렬 수식, 무수정 기준의 완전 재현, 실제 입력 재생 및 해시 거부를 검사한다. 설치된MuJoCo3.17.0의local API와 [공식 동역학 설명](https://mujoco.readthedocs.io/en/stable/computation/index.html)을 확인했다.

초기 새단위테스트에서는 같은 quaternion끼리 차분할 때 생기는 부동소수점 잔차가 미세한 feedback을 만든 사례를 발견했다. 정확히 같은 배열인 경우 오차를0으로 두어 수학적 항등성을 유지하도록 수정했다. 대조군8개에서 기준 상태·속도가 bitwise 일치함을 확인했다. 시험 허용량이나 실제 예산을 완화한 수정이 아니다.

## 결과

기준 구속은 **113.466581973km/h**다. 아래 값은 세밀한 해상도이며, 비교쌍은 모두 이번 제어기 내의 같은 목표를 사용한다.

### 끝 추가 각속도0인2° smootherstep 목표

- feedforward-only: 손목 목표 추적 RMSE **0.900954°**, 최대기준대비회전 **4.239217°**, 구속 **114.169816479km/h(+0.703235)**, 양의 성분 일 **+0.891794J**. 자세·일 미통과.
- 20Hz feedback: 손목 목표 추적 RMSE **0.217934°**, 최대기준대비회전 **1.995662°**, 구속 **114.284942232km/h(+0.818360)**, 양의 성분 일 **+1.770085J**. 공중심이동4.832888mm·방출방향차0.422528°로 자세 검사는 통과했으나 **일 예산은 미통과**다.

이 비교는 목표 궤적을 따라가는 제어 오차의 감소이며 실제 손목 자세의 측정 오차 감소나 선수 성능 향상이 아니다. 모델 어깨 회전의 한 성분 양의 일은+2.761671J, 어깨 회전 순일은+1.650703J였고, 다른 성분에서 줄어든 일이 있어 총 양의 일 변화와 다르다. 회전 성분을 해부학적 어깨 내회전 토크로 부르지 않는다.

### 끝 추가 각속도200°/s인2° cubic-in 목표

- feedforward-only: 손목 목표 추적 RMSE0.468415°, 최대회전3.334672°, 구속 **114.839198404km/h(+1.372616)**, 양의 일 **+5.975383J**.
- 20Hz feedback: 손목 목표 추적 RMSE0.452722°, 최대회전2.824935°, 구속 **115.128154614km/h(+1.661573)**, 양의 일 **+8.587344J**. 공중심이동3.714679mm·방출방향차0.521638°로 자세는 통과했지만 추가 일을 요구해 미통과다.

기존+1.665와 비슷한 숫자가 다시 나왔어도 같은 능력 향상으로 채택하지 않는다. 이전 원후보와 이번 목표 정의/제어 방법은 다르므로 두 숫자를 동일한실험의 오차 개선 전후로 취급하지 않는다.

### 작은0.5° cubic-in 목표,20Hz

구속은113.919473302km/h로 **+0.452891km/h**, 최대회전0.425336°와 손목 목표추적RMSE0.054716°다. 자세는 유지됐지만 양의 일이 **+1.744865J**로 역시 미통과다. 작은 각도나 작은 추적 오차만으로 에너지 전달 효율이 개선됐다고 판단할 수 없다.

24조건 모두 입력peak제한을 지켰고 자세 검사는19개에서 통과했다. 그러나 **일 예산 통과는0개, 최종 조건부 증가 후보도0개**다. 실제입력 제한과 일 예산 제한은 서로 다른 검사다. 두 해상도의 증가량 차이 최댓값은0.0000022438km/h였다. 이번 미통과를 수치 적분 오차로 설명할 근거는 없다.

모든 실행/실패는 [report.json](results/report.json)에 보존했다. 무수정 목표8개 대조군은 원기준 상태·속도를 정확히 재현했으며,48개 후보도 채택된 실제 입력만으로 재적분한 상태·속도가 저장 상태와 bitwise 일치했다. 별도 회계의 구속·양/음의 일·peak와 기존gate판정도 일치했다. [numerical_verification.json](results/numerical_verification.json) 참조.

## 실효성 해석과 다음 작업

이번에 나아진 부분은 **제한된 입력으로 목표 자세를 추적하는 성능**이다. 실제 개입 구속 향상이나 그효과의 오차범위를 확인한 것은 아니다. 원래1.665의 실제 효과구간, 손가락 접촉·3D공회전, 제구목표는 미검증으로 유지한다. 이전9개 민감도의+0.561~+1.775km/h 역시 실제 신뢰구간이 아니다.

다음 제어 변경은 feedback gain이나 손목 각도를 더 키우는 탐색보다 **DOF별 양/음의 일과 외부 어깨 순일을 함께 고려하는 제한 제어**여야 한다. 기준동작이 가능한해임을 보존하고, 비례적으로 전체입력을 끊어 자세를 잃는 이전 보호기를 성공한방법으로 채택하지 않는다. 현행 최대 입력 제한만의 feedback은 일 제약을 보장하지 않으므로 최종후보선정에는 사용하지 않는다. 단, 이24조건의 실패가 모든 가능한 동작의 불가능성을 증명하는 것은 아니다.

실제효과판정에는 같은선수의 실제기준/수정투구, 구현된동작 확인, 구속과부하/일 동시측정이 필요하다. 사람의개입자료가없는데 모델단위테스트나 적분재현으로 이를대체하지않는다. 성능향상후보가미통과이므로 성공영상은export하지않았고 기존과학gate를advance하지않았다. 자동루틴·선수모집·외부연락·배포·PR병합은하지않았다.
