# 동기화된 손끝–공 영상과 투구 기록 확보 결과

2026-11-13. 판정 기준은 결과를 확인하기 전에 `PROTOCOL.md`로 고정하고 커밋했다. 논문·보충자료, 영상 제공업체, 국제 공개 저장소를 세 워커가 병렬로 조사했고, 주 작업은 저자 공개 원영상과 파일 검산을 맡았다.

## 결과

이번 확인 범위에서 **후면·측면의 동기화된 고속 손끝 영상과 같은 투구의 구속·RPM·무브먼트 기록을 모두 확보한 자료는 0개**다. 자료가 전 세계에 없다는 뜻은 아니다. 원문에 촬영 방법이 있다는 사실, 공개 영상이 있다는 사실, 같은 투구의 측정 기록이 있다는 사실을 각각 확인했다.

새 MP4 8개를 실제로 받았다. 6개는 투구 촬영 예시이고, 1개는 논문 시연 편집물, 1개는 스켈레톤 재생이다. 파일 8개를 서로 다른 투구 8구로 세지 않는다. 두 시야를 확보하지 못한 영상끼리 짝짓지 않았고, 다른 선수의 측정표도 연결하지 않았다. 파일 해시·바이트·디코드 결과는 `ACQUISITION.json`과 `VALIDATION.json`에 기록한다. 원영상과 상세 로그는 ignored `artifacts/source-search-001/`에 보존한다.

적격 자료가 없으므로 이번 작업에서는 손–공 동역학을 새로 실행하거나 구속·RPM·IVB·HB 예측 오차를 산출하지 않았다. 오차는 0이 아니라 **산출 불가**다. 새 개선 영상과 앱 통합도 없다. 기존 모델의 결과·설정·검증 기준은 바꾸지 않았다.

Shin 파일은 한 워커의 다운로드가 HTTP 403이었지만 다른 워커는 공개 URL에서 성공했다. 성공한 파일을 공유해 해시와 내용을 독립 재검산했다. 시간은 0.04~3927.36초, 간격은 약 0.04초(25Hz)다. 논문의 4대 동기 60fps 손가락 검증은 별도의 느린 굽힘 운동이다. 이를 야구 이탈의 고속 다중시야 자료로 바꾸어 해석하지 않았다.

BaseballAero 공개 평가 영상의 선수는 **Kyler Briel**이고 기존 별도 기록표는 **Branson** 자료다. 새 Kyler 예시를 기존 Branson #4/#8의 구속·RPM·공 상태와 연결하지 않는다. 공개 보고서의 포심 before/after 영상도 투구별 원시 기록표나 측면 영상의 대체물이 아니다.

## 이미 조사했던 자료의 추가 확인

- [Kusafuka 2023 PLOS 원문](https://doi.org/10.1371/journal.pone.0290042)은 후면·측면 960fps 동기 촬영 연구로 방법상 가장 가깝다. 이번에는 DOI에 연결된 Figshare 목록을 다시 조회했다. 공개 항목은 그림 4개·표 2개·S1 DOCX 1개였고, 그 목록에서 새 원영상은 확인하지 못했다. 본문의 촬영 규모를 공개 원영상 확보 건수로 세지 않는다.
- OBP 공개 release 목록에서도 새 손끝/RPM 묶음을 확인하지 못했다. 기존 Prime 카메라 자료에 RPM이 추가되었다고 판단하지 않는다.
- TrackMan 공식 문서는 Edgertronic 영상과 기록을 PlayID로 연결하고 촬영 속도·셔터·릴리스 프레임을 전달하는 구조를 설명한다. 이는 고객 시스템의 연결 방법이며 공개 원자료 자체는 아니다.
- Matsuo 2024 논문은 다수 카메라를 사용한 손·공 관측 후보지만 출판사 본문 접근이 막혔다. Figshare DOI 조회 결과 0개라는 사실만으로 모든 경로에서 비공개라고 단정하지 않았다.

## 다음에 모델을 연결할 때 필요한 것

최소 묶음은 두 원영상, 촬영 시계·동기 근거, 카메라/길이 보정, 투구 ID, 같은 ID의 구속·RPM·무브먼트 기록이다. 기록의 무브먼트가 중력 포함 변위인지 유도 무브먼트인지와 단위·좌표도 필요하다. 전신까지 연결하려면 같은 투구의 몸 관측과 정렬 근거가 추가로 필요하다.

확보 후에는 손끝·공 중심·마지막 접촉을 장비 결과를 보지 않고 판독하고, 일부 시야/프레임을 제외 평가로 남긴다. 손 모델이 추정한 상대3D를 보정된 실측3D로 취급하지 않는다. 손–공 모델이 예측한 방출 속도·회전 상태를 먼저 평가하고 그 상태로 비행을 적분해 IVB/HB·통과점을 비교한다. 실측 RPM을 입력한 비행 재현과 손가락에서 RPM을 예측한 결과는 별도 출력한다.

현재 가장 직접적인 확보 경로는 동기 두 시야를 이미 촬영한 연구팀의 익명화 자료 또는 고속영상과 장비 CSV를 함께 가진 팀의 내보내기다. 공개 자료만 계속 찾는 동안에는 새 후면 영상으로 손끝·실밥 검출의 일반화를 시험할 수 있다. 그 시험으로 접촉력, 구속/RPM 변화나 훈련 효과가 검증되는 것은 아니다. 이번 작업은 외부 연락·유료 구매·계정 접근을 하지 않았다.

## 실행·검증 범위

- 새 worktree와 브랜치를 최신 원격 main에서 만들고 사전 기준을 먼저 커밋했다.
- `requests`로 저자 페이지·고정 커밋의 파일·공개 보충자료를 받았고 `hashlib`로 해시를 확인했다. SpinTracker 파일 5개는 Git blob SHA1도 원격 트리와 대조했다.
- `cv2.VideoCapture`로 영상 전체를 순차 디코드했다. 공급업체 영상의 헤더·디코드 프레임 수 차이는 별도 기록하며 촬영 시계로 사용하지 않는다. 대표 원본 프레임을 직접 확인했다.
- 공급업체 4개 파일은 기본 디코드 347/402/381/322프레임, `-ignore_editlist 1` 조건은 354/429/429/325프레임으로 헤더와 일치했다. FFmpeg 8회 모두 종료 코드 0, 오류·손상 로그 0이었다. 차이는 MP4 편집 목록의 표시 구간 처리로 설명된다. 촬영 당시 시간축·내보내기 이전 프레임 보존까지 확인한 것은 아니다.
- ZIP/DOCX 구성원과 XLSX 시트/열/간격을 실제로 열어 검사했다. PDF는 원문 텍스트와 필요한 표지 렌더를 확인했다. 출력 인코딩 실패와 파일 읽기 성공을 구분했다.
- 모델·애플리케이션 코드는 변경하지 않았다. 기존 모델 회귀테스트를 재실행하지 않았으며 이를 통과했다고 보고하지 않는다. 파일 검산과 자료 적격 판정도 모델 정확도 검증과 다르다.
- 원본 영상·표·논문 파일·개인 경로는 커밋하지 않는다. 라이선스를 영상 전체의 재배포 허가로 확대하지 않는다. 연구용 코드의 라이선스를 앱 사용 허가로 간주하지 않는다.

최종 집계 검산은 `python artifacts/source-search-001/validate_sources.py`로 실행했다. 파일 20개 SHA256·바이트 검사 20통과/0실패, 원격 Git blob 대조 5통과/0실패, 보충 ZIP 구성 검사 2통과/0실패다. 영상 8개, 센서 데이터 98,184행의 구성도 확인했다. 초기 집계는 `openpyxl` 부재와 기본 CP949 읽기 때문에 두 번 실패했고, 패키지 설치 없이 표준 ZIP/XML과 명시적 UTF-8 읽기로 복구했다. 이 복구 전후를 `VALIDATION.json`에 남겼다. **파일 검사 통과와 자료 적격 0건은 서로 다른 판정이다.**
