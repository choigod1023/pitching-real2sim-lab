## 실제 구위 원자료 접근

Mendeley/Statcast CSV의 기존403실패를 보존하면서, 다른 공식 공개 경로인 [MLB schedule](https://statsapi.mlb.com/api/v1/schedule?sportId=1&date=2025-06-01)이 실제로 제공한 [경기 feed 링크](https://statsapi.mlb.com/api/v1.1/game/777677/feed/live)에서 JSON을 확보했다. CSV를 받은 것은 아니다.

사전 날짜의 완료 정규시즌 경기 중 gamePk오름차순 첫 경기777677을 사용했다. **69AB·256투구·8투수**가 있으며 회전·무브먼트·속도·위치 등 수치25개는 각각256/256유한값이었다. 두 팀의 boxscore 투구수122+134와일치했다. 성적/구위가 좋은 경기만 골랐다는 뜻이 아니다.

기존 CSV 접근 실패와 실제 JSON 접근 성공을 구분했다. 원문/투구별 값은 Git제외캐시에만 저장했고 코드·집계·출처 해시를 공개한다. MLB자료를 OBP의CC BY라이선스 자료로 재분류하지 않았다. 출처의 공개GET성공이 원문재배포허용을 뜻하지 않는다.

파서는 다음 함정을 처리한다.

- AB도중 투수/타자가 바뀌면 전체 matchup으로 과거 투구를 잘못 연결할 수 있어 격리한다. 이번 표본에서는 첫 투구 후 신원교체0건이었다.
- 이벤트 count는사후값이다. 비투구 이벤트의 자동판정까지 반영해 사전 balls/strikes를 복원했고,256투구와69AB최종count가 모두일치했다.
- 공식 pitchCodes의 원문bool을 보존한다. foul tip의 swingMissStatus=true를 연구용헛스윙으로 즉시바꾸지 않았다.
- Feed의별칭필드에 대한단위/좌표/시점근거는UNKNOWN으로보존하고임의변환/3D회전복원을하지않는다. 공식metrics의유사이름만으로자동확정하지않았다.
- 원본 응답bytes/URL/접근시각/해시를보존하고캐시변조·HTML응답·중복·결측을검사한다.

부모worktree에서도실제GET→캐시→파서를재실행해동일feedSHA256과동일집계가나왔다.별도직접계산으로256투구의신원/사전사후count·6,400개수치원값을대조했다. [MLB 상세보고서](../pitch_quality/MLB_DATA_FINDINGS.md)에필드·단위·제약·명령을기록했다.

현재 technical_access_ready=true지만 conditional_study_ready/body_to_spin/3Dspin/개입효과는false다. 이 경기의 투수/투구는 OBP의35쌍과같은사람·동작이아니며신체좌표를가져다붙이지않는다. 원문단위확정/충분한반복경기/구위결과정의 없이관계모델을구위향상이라고주장하지않았다.
