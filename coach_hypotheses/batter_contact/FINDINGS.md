# 타자 반응 연결과 투구 장면 구현 결과

2026-10-30. **타자의 스윙 판단·통계적 미스 확률을 결합하는 API와, 실제 투수·타격 궤적을 배치한 기하 데모를 구현했다. 투수의 관절을 바꿔 성능을 높인 결과는 아직 없다.** 새 성공 보고 경로는 검증한 투구 장면 영상이 없으면 성공을 반환하지 않으며 athlete_candidate 성공은 차단한다.

## 실제 구현한 연결

PR129에서 저장한 GB0/GB1의 knot·투수별 평균·scale·타자 절편·회귀계수를 source SHA256에 맞춰 복원했다. 검사 자료에서 다시 학습하지 않았다. 기존 MLB 관측 행을 넣으면 P(swing), strict S/W 또는 공식 미스 조건부 확률을 반환한다. 이어 노스윙, 스윙/해당 미스, 스윙/그외의 확률을 계산한다.

복원한 두 모델에서 **각65,236개, 총130,472개 기존 확률을 대조했고 최대 차이는0**이었다. 이는 기존 계산의 재현이며 물리 시뮬레이션이나 실제 미래 선수 결과의 오차0이라는 뜻이 아니다. 합계1 조건도 확인했다.

예시 입력은 gamePk776507 / atBatIndex0 / pitchIndex3, 타자ID702616이다. GB1의 스윙 확률은11.48%, 스윙 조건부 strict S/W 확률은12.85%, 한 공당 스윙/SW 결합 확률은1.48%다. 노스윙88.52%와 스윙/그외10.01%를 더하면100%다. 실제 타자의 스윙 궤적을 예측했다는 뜻은 아니며, 이 MLB 수치를 영상의 OBP 선수에게 대입하지 않았다.

공식 미스에는 파울팁이 포함되고 strict S/W에는 Q가 들어가지 않는 등 정의 차이가 있다. 따라서 swing_other를 물리적 컨택이라고 부르지 않았고 `physical_contact_probability=None`으로 둔다. OBP 자세나 가정 공 궤적을 MLB 실측 원필드처럼 보내면 API가 거부한다. 몸→통계 공 지표의 검증된 매핑은 여전히 미확인이다.

## 결합 확률의 진단

6~7월 학습20스윙·2경기 조건에 맞는 투수334명의8월32,910 FF 투구에서, 기존 모델의 스윙 확률과 조건부 미스 확률을 곱했다. 예전 스윙만 검사한333명·16,163개와 분모가 다르다. 이 진단은 **이미 사용한8월 자료의 통합 확인이며 새로운 미사용 검증 또는 사전 가설 통과가 아니다.**

| 한 공당 타깃 | GB0 결합 Brier | GB1 결합 Brier |
|---|---:|---:|
| strict S/W 미스 | 0.0768281 | 0.0758680 |
| 공식 통계적 미스 | 0.0872410 | 0.0859912 |

이는 구위 정보의 결합 예측 진단이다. PR129의 미스/스윙 Brier0.132264와 이 수치를 비교해 큰 오차 감소를 주장하지 않는다. 조건부 모델의 곱이 실제 타자의 반응 또는 인과 효과를 정확히 재현한다는 증거도 아니다.

## 영상의 실제 자료와 가정

투수는 OBP830의1615_1, 타자는 별도 머신 타격 자료의000004/103_1이다. 타자 원 C3D 후보 `000004_000103_75_236_R_003_972.c3d`는360Hz·m 단위이고 처리 표와 프레임 수가 일치했다. 원 손목 마커 중점과 처리 손목 중심 거리의 중앙값은0.163mm다. 이는 대응/단위 확인이며 해부학적 정확도0.163mm라는 뜻이 아니다. 명시적 raw trial ID 매핑 대신 프레임 수·좌표 대응 후보라는 한계를 남겼다.

타자 자료는 공식 `dataset-v1`의 hitting_landmarks.zip·hitting_c3d.zip을 확보했고 GitHub asset SHA256과 일치했다. 원본 ZIP·CSV·C3D는 Git에 포함하지 않았다. 투구 자세는 기존 처리20Hz 좌표를 추가 필터링 없이 재사용했다. 타자도 제공 좌표를 사용했고 추가 필터를 적용하지 않았다.

두 실험의 좌표는 문서에 따라 수평180도 proper rotation과 고정 병진으로 배치했다. 투수의 FP10 수평 hip 기준을 장면의18.44m에 둔 것은 실제 구장 보정이 아니다. 매 프레임 몸통/손목 정렬이나 관절 변경은 하지 않았다. 모든 투수 뼈 길이의 원자료 대비 변환 차이는 최대3.39e−12mm였다. 이 수치는 강체 변환의 연산 일치도다.

공은 투수 손 중심을 대리 원점으로 삼고 기록137.44km/h를 초기 속력으로 입력한 중력 포물선이다. 실제 방출 공 중심·속도벡터·스핀·공기저항을 측정하거나 역산한 것이 아니다. 기준 타격 시각의 sweet_spot을 지나도록 구성했으므로 그 시각의 근접은 **설계상 맞춤**이다. 근력·관절 토크·외부 일·실제 접촉력은 계산하지 않았다. 타구 속도·발사각도 None이다.

## +12ms 결과를 성공으로 바꾸지 않았다

투수 자세와 공 참조 궤적을 유지하고, 같은 타자 기록을0/+12ms로 이동했다. 배트 전체 대신 sweet_spot 주변 축의±50mm, 공 반경36.5mm와 배트 반경33mm라는 공학적 가정에 대해 근접을 검사했다.

- 기준0ms: 최소 축 거리0.0mm. 기준 정렬에 의한 값이다.
- +12ms: 0.1ms 격자에서 최소 축 거리2.49mm로, **두 조건 모두 설정한 근접 범위 안**이었다.
- +12ms의 가장 가까운 시각은 기준 접촉보다 약5ms 뒤다. 같은 한 프레임에서 배트가 다르게 보인다는 이유만으로 실제 미스로 판정하지 않는다.
- −20~+20ms의1ms 탐색에서−18~+20ms가 근접했다. +20ms 끝에서도 지속되므로 전체 허용 구간의 상한을 구하지 못했다. 이를 실제 타자의38ms 허용 범위라고 보고하지 않는다.
- 배트 반경28/33/38mm와 공 높이−10/0/+10mm의9조건에서도0/+12ms의 근접 결론은 같았다. 구간 시작은−16~−20ms였고 양의 경계는 계속 열려 있었다. 이것은 공학적 민감도이며 확률분포나95% 측정오차가 아니다.

0.2/0.1/0.05ms 비교에서 근접 판정과 탐색 구간은 같았지만 +12ms의 최소 거리에는 약0.96mm 차이가 남았다. 원 마커360Hz보다 촘촘한 계산이 실제 관측 해상도를 늘리지는 않는다. 별도 연속 최소화 검사에서는 최소 축 거리 약0.95mm, 가장 가까운 시각+5.033ms로 나왔다. 0.1ms 격자와는 약1.53mm 차이가 있었지만 근접 판정은 유지됐다. 이 절대 거리를 정밀 실측이라고 취급하지 않는다.

서로 다른 궤적을 정렬해 타이밍 근접을 계산하는 접근은 [2025년 연구](https://www.frontiersin.org/journals/sports-and-active-living/articles/10.3389/fspor.2025.1557145/full)와 관련되지만, 원자료·대상·기하 정의가 달라 그 논문의 결과 재현이나 성능 비교는 아니다. 현재 결과로 특정 투수나 타자에게12ms를 바꾸라고 권고하지 않는다.

## 영상과 코드 검증

`media/pitcher_batter_overlay.mp4`는1600×1000,30fps, **382프레임 약12.7초**다. 전체 투구를 약1/10배로 보여준 뒤 접촉 구간을 약1/30배로 다시 보여준다. 주황은 원 투수, 파랑은 기준 타자, 분홍은12ms 지연 타자다. 타자 축/점 위치 차이를 표시하고 투수 수정0°/0mm·힘/일 미평가·실제 구위 향상 미검증을 화면에 표시한다. 투수 기록 종료 뒤 마지막 자세 유지도 표시한다. 헤드 원과 배트 외곽선은 도식이다.

전체 FFmpeg 디코드와382프레임 읽기를 확인했고, 첫·중간·끝·접촉 대표 프레임을 시각적으로 검사했다. 공유 사본의 SHA256도 원 생성 영상과 같다. 성공 보고에는 이 MP4와 바로 표시할 Markdown 태그가 포함된다. 그래프 영상으로 대체하지 않는다.

새 테스트15개가 통과했다. 전체419개 중407개 통과·기존 오류10개·skip2개이며 새 실패/오류는 없다. 기존 오류9개는 OpenSim 부재,1개는 로컬 formula_checks.json 부재다. 자기 worktree의 model.xml 테스트 부작용만 복원했다.

첫 실행에서 사전 문서의 고정 ID와 숫자 정렬 규칙이 충돌해 중단했다. **103_1 기하 결과를 계산하기 전** `AMENDMENT_01_IDENTITY.md`를 커밋해 ID만 정정하고 원 규칙을 유지했다. 이후 영상/manifest 생성은 끝났으나 Windows cp949 콘솔의 en dash 출력이 실패해 UTF-8 출력 helper로 고쳤다. 두 실패 로그를 보존했고 마지막 전체 CLI는 exit0으로 끝났다. 결과를 지우거나 유리한 타이밍/선수로 바꾸지 않았다.

## 남은 연결

현재 타자의 확률 반응과 실제 배트 궤적 계산을 프로그램에서 다룰 수 있다. 그러나 동일 투구의 신체→직접 공 상태→실제 타자 스윙·타구를 하나로 검증한 것은 아니다. 같은 힘·일에서 투수 관절을 조정해 실제 구속·구위·제구를 개선하는 가설은 여전히 미검증이다. 기존 Real2Sim gate도 바꾸지 않았다. 그 근거가 생기기 전에는 이 모듈의 athlete_candidate 성공을 허용하지 않는다.
