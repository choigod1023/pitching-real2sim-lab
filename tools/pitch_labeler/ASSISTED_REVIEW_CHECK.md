# 자동 후보 검수 적용 확인 — 2026-11-13

## 변경

원본 프레임 전체를 사람이 처음부터 표시하던 흐름에 기존 공 추적기의 후보를 먼저 표시한다. 맞음은 승인 후 다음 미확인 프레임, 틀림은 좌표 수정, 안 보임은 판독 불가로 저장한다. 릴리스는 앞뒤 원본 사진을 비교해 별도로 확인한다. 기존 수동 기록을 자동 후보로 덮어쓰지 않는다.

## 실제 영상 계산

고정한 proposal_union 경로를 사용했다. 운영자가 원영상에서 검색 영역의 양 끝을 지정했고, 원본 SHA-256을 확인한 뒤 실제 RGB 프레임을 처리했다. 구속 기록이나 기존 사람 판독 좌표를 후보 선택에 쓰지 않았다.

| 투구 | 전체 프레임 | 공 위치 후보 | 분리 검색 후보 |
|---|---:|---:|---|
| mlb-777438-2-top | 41 | 12 | 176 → 177 |
| mlb-777427-2-top | 43 | 12 | 201 → 202 |
| academy-000006 | 37 | 6 | 77 → 78 |
| academy-000018 | 38 | 11 | 124 → 125 |
| 합계 | 159 | 41 | 4개 |

41개는 생성한 후보 수이며 올바른 검출 수가 아니다. 나머지 118프레임에는 공 없음이나 보간점을 자동으로 채우지 않았다. 분리 후보는 연속 검출의 시작점에서 만든 검색 제안이므로 실제 손 접촉 여부를 사람이 확인해야 한다. 이 후보를 본 판독은 독립 블라인드 정답으로 쓰지 않는다.

## 검증

- `node --test tools/pitch_labeler/*.test.cjs`: 7개 통과, 0개 실패.
- `python -m unittest discover -s tools/pitch_labeler -p "test_*.py"`: 2개 통과, 0개 실패.
- 후보 미확인 상태의 제출 차단, 거절 뒤 좌표 미완성 유지, 좌표 수정·판독 불가 구분, 과거 수동 기록 보존, 후보와 다르게 조작한 승인값 거부, 서버 재시작과 작업자 분리, 보조 판독의 블라인드 구분을 검사했다.
- 별도 QA 작업자와 저장 폴더에서 실제 MLB 원본으로 승인 → 다음 프레임 이동, 틀림 → 원본 클릭 수정, 안 보임, 릴리스 확인, 새로고침 후 복원을 직접 확인했다. 야외 영상의 후보와 분리 사진 전환도 확인했다. 이 UI 시험값은 실제 작업자 판독에 합치지 않았다.
- 로컬 서버와 기존 외부 HTTPS 주소에서 두 작업자의 배정 목록과 원본 PNG를 조회했다. 실제 R01의 기존 revision 7과 파일 SHA-256이 변경되지 않았음을 확인했다. R02는 revision 0을 유지했다.
- 기존 서버를 새 코드로 교체했고 외부 터널과 작업자 링크는 유지했다. 원본 영상·프레임·키·실제 판독·QA 화면은 Git 밖에 저장했다.

실제 사람이 확정한 판독이 충분히 모이기 전에는 검출 정확도 상승이나 작업 시간 단축률을 주장하지 않는다. 이번 변경은 검수 방식과 데이터 보존 기능이다.
