# 논문을 참고한 공통 수정 규칙 시제품

2026-10-30. 투구마다 별도 최적화를 하는 대신 **하나의 함수가 현재 관절 상태를 보고 수정량을 정하도록** 구현했다. 새 결과 계산 전에 [PROTOCOL.md](PROTOCOL.md)를 `37cdc0f`에서 커밋했다. 논문 원문 근거와 확인 범위는 [SOURCES.md](SOURCES.md)에 정리했다.

**코드와 검증 절차는 구현했지만, 여러 투구에서 양의 구속 변화가 성립하는 공식을 얻지는 못했다.** 이는 훈련·의료 조언이 아니다. 실제 구속 효과나 부상 위험 감소를 확인한 결과도 아니다.

## 어떤 근거를 어떻게 반영했는가

- 선수 간 평균 관계와 선수 내 변화 관계를 구분한다는 원칙을 참고했다. 선수별 기본 모델과 기준 부하는 유지한다.
- 위치·속도 상태를 입력으로 제어량을 정하는 방법을 참고했다. 투구 ID별 답안표를 만들지 않는다.
- 실제 동역학 안에서 부하와 성능을 함께 검사한다. 높은 속력이 나와도 제약을 어기면 기각한다.
- 모든 투구를 고정된 이상 시퀀스로 강제하지 않는다. 관찰적 유의 구간을 최적 수정 시점이라고 가정하지 않는다.

논문들은 이번 12계수 함수나 입력 범위의 정답을 제시하지 않는다. 이번 구현은 논문에서 참고한 원칙과 기존 코드에서 실행할 수 있는 제한된 탐색 기저를 조합한 **우리의 연구 가설**이다. 딥 강화학습이나 실제 근육 제어를 재현한 결과로 부르지 않는다. 구체적인 자료 링크와 논문별 제한은 SOURCES에 있다.

## 공식의 구조

투구 i의 개입 직전 모델 상태를 x_i라 하고, 같은 선수의 학습 투구들로 정한 평균과 척도로 표준화한다.

```text
z_i = clip((x_i - training_mean) / training_scale, -2, 2)
a_i = tanh(W @ [1, z_i])
수정 입력 = 원래 입력 + 기존 시간 패턴 × a_i × 원래 입력 peak의 2%
```

W는 모든 투구가 공유하는 3×4 계수다. 세 출력은 팔꿈치/전완 marker-roll/손목의 입력 배율이다. 모델 상태는 BR-60ms 이하 마지막 시각의 팔꿈치 힌지 각도, 그 속도, 손목 마커 회전속도 노름이다. 이 좌표를 해부학적 각도 처방으로 해석하지 않는다. 방향은 PR135의 후보 패턴에서 내부 관절 부분만 고정해 빌렸고 외부 root 힘/토크의 입력은 수정하지 않는다. 이는 좁은 기저이며 가능한 모든 관절 수정이 아니다.

특징이 학습 최소~최대 범위 밖이면 수정량을 0으로 두고 **적용 보류**한다. 이 범위는 정확도나 안전이 검증된 구간이 아니며 작은 표본 밖의 외삽을 피하기 위한 규칙이다. 결과를 보고 범위를 넓히지 않았다.

현재는 개입 직전 상태로 마지막 구간 입력을 한 번 정하는 오프라인 정책이다. 공칭 BR을 알고 정렬하므로 온라인 실시간 제어가 아니다. 전신 시계열 정책, 골반·몸통 개입, 실제 근육 활성 제어는 이 시제품에 없다.

## 여러 투구에서 함께 검사한 제약

3034_1/2/3만 계수와 스케일 적합에 사용했다. 목표는 평균 이득이 아니라 **세 투구 중 가장 작은 구속 변화량의 최대화**다. 한 투구의 큰 이득으로 다른 투구의 손해를 덮지 않도록 했다. 각 투구의 RK4 원래 dt와 dt/2에서 실제 힘 입력으로 적분하고 상태 재설정 없이 검사했다.

새 C 기준은 **A 전체 AND B 전체 AND root 힘 벡터 최대값 비증가**다. 이전에 빠졌던 전체 순 일과 외부 그룹 일도 포함한다. A/B는 이전 정의 그대로 따로 기록했다. 입력 최대값 투영은 유지하고 자세 3도/20mm/1도, 동일 초기 상태, 해상도 차이도 검사한다. 이 기계적 C 기준을 근육 용량·안전의 검증으로 바꾸지 않는다.

기록 레이더 구속은 학습·선택·특징·분포에 쓰지 않았다. 일반 관성과 15cm 그립, 20Hz 처리, 기존 선수별 고정 분절 길이는 바꾸지 않았다. PR136의 입력과 기준 적분을 해시로 대조하고 재사용했다.

## 실제 계산 결과

총 **93개 정책 = 279개 투구/해상도 쌍 = 558회 후보 적분**을 평가했다. 기준 검산·선택 결과 독립 재생은 별도다.

- 0 시작점: 13개 정책 평가 후 1 iteration에서 0 정책으로 로컬 종료했다. solver success는 구속 변화의 성공이 아니다.
- 두 번째 시작점: 사전에 정한 80개 정책 평가 예산에 도달했다. 최적해 수렴은 확인하지 못했다.
- 학습 3구 모두에서 C·자세·양의 변화·해상도 조건을 통과한 정책은 **0개**였다.
- 제약을 무시했을 때 최저 구속 변화가 가장 컸던 실패 정책도 세 투구의 변화가 +0.023334/+0.012899/+0.010763km/h에 그쳤고, 모두 C를 위반했다. 이를 유효 후보로 채택하지 않았다.
- 선택된 결과는 **W=0, 원래 입력 유지, 구속 변화 0km/h**다. 이 제한된 기저와 계산 예산에서의 결과이지 공통 규칙의 존재를 부정하는 증명은 아니다.

외부 힘 입력을 그대로 유지해도 외부 일이 같지는 않았다. 위 실패 정책에서 3034_1의 외부 어깨 병진 순 일이 약 **+0.030143J** 증가했다. 일은 힘과 이동 속도를 함께 적분하기 때문이다. 반면 전체 순 일은 줄었다. 전체 합 하나만 보거나 입력 힘이 같다는 이유만으로 비용 검사를 생략하면 놓칠 수 있는 차이다.

## 적합에서 제외한 2구의 평가

선택 W와 scaler를 `frozen-policy.json`에 먼저 저장한 뒤 3034_4/5의 평가 입력을 불러왔다. 평가 결과로 선택이나 범위를 바꾸지 않았다. 이 두 투구도 과거에 이미 본 개발 자료여서 독립 미사용 검증이라고 부르지 않는다.

| 투구 | 학습 상태 범위 | 처리 | 모델 구속 변화 | 개선 판정 |
|---|---|---|---:|---|
| 3034_4 | 벗어남 | 적용 보류, 원래 입력 | 0km/h | 미통과 |
| 3034_5 | 벗어남 | 적용 보류, 원래 입력 | 0km/h | 미통과 |

학습 3구의 손목 모델 속도 노름 범위는 6.665~8.507rad/s였다. 3034_4는 9.029, 3034_5는 5.874rad/s였으며 팔꿈치 속도도 범위를 벗어났다. 한 선수의 세 투구만으로도 나머지 동작 상태를 덮지 못했다. 보류를 정확한 예측이나 성능 개선으로 세지 않는다. 선택 결과의 저장 힘을 독립 재생하고 accounting을 검산했다.

## 무엇이 아직 해결되지 않았는가

- 같은 계수를 공유하는 프로그램은 구현했지만, 효과가 검증된 비영(0이 아닌) 정책은 없다. 다른 선수 일반화는 이번에 실행하지 않았다.
- 좁은 기존 입력 방향을 배율 조정한 탐색이므로 더 넓은 관절·시계열 정책에서의 가능성은 미확인이다.
- 세 학습 투구만으로 12계수와 적용 범위를 결정했다. 표본이 작고 자료는 모두 개발 자료다.
- 관성·해부학적 축·실제 근육 능력·손/공 접촉·이탈의 기존 불확실성을 제거하지 않았다. 기존 약 16.7km/h 모델 차이를 줄인 결과가 아니다.
- 실제 수정 투구의 관측 정답이 없어 효과의 95% 구간이나 오차 범위 밖의 효과를 계산하지 못한다. 구위·회전·제구 효과도 검증하지 않았다.
- 합격한 새 양의 후보가 없으므로 새 향상 영상을 만들지 않았다. 전역 연구 gate나 자동 루틴도 진전·재개하지 않았다.

## 이후 구현 순서

1. **관측 기반 규칙과 개입 효과를 분리한다.** 더 많은 선수의 반복 투구에서 전신 각도·각속도·단계별 타이밍을 추출해, 선수 간/선수 내 관계와 필터 민감도를 검산한다. 이미 본 자료와 새 분할을 명확히 표시한다.
2. **입력 방향 기저를 다시 설계한다.** 한 실패 후보의 배율 조정에 묶이지 않고 관절별 시간 경로를 표현하되, 단순히 자유도를 늘리기 전에 변화가 실제 관절축과 어떻게 대응하는지 확인한다. 전신 개입은 발 접촉·지면반력·외부 일·근육 조건 검증 후에 연결한다.
3. **여러 상태를 동시에 다루는 정책을 학습한다.** 단계별 시계열과 선수별 고정 보정을 쓰고, 여러 투구의 비용을 동시에 검사한다. 적용 보류 범위를 평가 결과에 맞춰 넓히거나 힘 용량을 올리지 않는다.
4. **새 평가 자료에 한 번 적용한다.** 진정한 미사용 투구/선수를 확보한 뒤 계수·스케일·보류 규칙을 고정해 평가한다. 실제 선수에게 제안할 근거는 공/손 이탈과 부하 예측 및 실제 개입 검증까지 필요하다.

## 파일과 실행

- `policy.py`: 상태 특징, train-only 스케일링, 공유 정책, C 검사, 선택 규칙.
- `study.py`: 기존 입력 해시 검증, 실제 적분, 세 투구 공동 최적화, 고정 후 평가.
- `test_policy.py`: 새 함수와 실패/보류/자료 분리의 회귀 검사.
- `SOURCES.md`, `PROTOCOL.md`: 원문 확인 범위와 사전 설계.
- `results/report.json.gz`: 모든 실패·중간 계산·선택 결과의 무손실 압축. `summary.json`에 원문/압축 해시를 기록했다.

작업 worktree의 Python은 `../.venv/Scripts/python.exe`다.

```powershell
python -m unittest coach_hypotheses.shared_policy.test_policy -q
python -m coach_hypotheses.shared_policy.study --source ../pitch-transfer-validation-20261030/artifacts/pitch-transfer --out artifacts/shared-policy
# 전체 테스트: unittest.defaultTestLoader.discover('.') 결과를 이전 오류 ID와 비교
```

새 검사 **11/11 통과**. 전체 **490개 중 478 통과, 기존 오류 10개, skip 2개, 새 오류/실패 0개**다. 기존 오류는 opensim 부재 9개, 로컬 formula_checks.json 부재 1개다. 초기 단위 검사의 한 fixture는 이미 peak에 있는 양의 입력에 양의 수정을 주어 변화가 없었으며, fixture를 음의 수정으로 고쳐 cap 유지와 실제 변화를 함께 검사했다. 실행 데이터나 합격 기준은 바꾸지 않았다. 과학적 효과 미통과와 코드 테스트 통과를 구분한다.
