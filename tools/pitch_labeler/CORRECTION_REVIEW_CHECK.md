## 보존과 확인 방식

- 최초 좌표, 릴리스 값, 접수 사본과 접수 이력을 유지한다.
- 후보별 맞다·아니다·모르겠다와 시각, 후보 전체 사본·해시를 별도 저장한다.
- 후보의 원본·제출 ID·현재 좌표·릴리스 문맥이 바뀌면 승인 목록에서 제외한다.
- 답변 저장 전에 대기 중인 자동 저장을 마치며, revision 충돌 시 다른 탭의 작업을 덮어쓰지 않는다.
- 근거가 다른 후보로 바뀌면 이전 답변을 승계하지 않는다. 변경 이력은 남긴다.
- 승인 목록은 별도 해석층이며 원래 연구 결과나 릴리스 검증을 자동 대체하지 않는다.

## 검증

실제 자료의 복사본을 별도 포트에 띄워 브라우저에서 맞다·아니다·모르겠다를 각각 저장했다. 새로고침 후 18건 중 미확인 15·맞다 1·아니다 1·보류 1을 확인했다. 서버 JSON에도 답변 3개와 이력 3개가 저장됐으며, 기존 `drafts`, `sceneSubmissions`, `sceneSubmissionHistory`, `result`, `submittedAt`은 전부 동일했다. 원래 운영 기록에는 시험 답변을 넣지 않았다.

앞뒤 프레임을 볼 때 질문 대상 번호를 유지하고 답변 버튼을 잠그는 것, 대상 복귀 후 저장, 손에 있음 후보의 설명 표시를 브라우저에서 확인했다.

실행 명령:

```text
node --test tools/pitch_labeler/*.test.cjs
python -m unittest discover -s tools/pitch_labeler -p "test_*.py"
node --check tools/pitch_labeler/site/app.js
git diff --check
```

Node 테스트 23개와 Python 테스트 2개가 통과했다. 원본 보존, 후보 해시·작업자 검사, 오래된 후보 차단, 이력 누적, 저장 충돌, 오프라인 재전송 및 응답 유실 후 복구를 포함한다. 실제 영상 판독의 정답률 검증과는 구분한다.
