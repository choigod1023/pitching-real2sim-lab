# 공통 사이트와 씬 진행상태 확인 — 2026-11-13

이 문서는 당시 검증 기록이다. 이후 사용자 요청으로 공통 접속 코드를 제거했다. 현재 접속 방법은 README의 작업자 선택 절차를 따른다.

## 적용

작업자마다 다른 키 URL을 전달하던 방식을 공통 주소 + 팀 접속 코드 + 작업자 선택으로 바꿨다. 인증 후 전체 씬, 진행률, 입력 검사 완료 여부와 재확인 프레임을 한 화면에서 제공한다. 같은 브라우저에서는 작업자를 기억하고, 기존 키 URL은 읽은 뒤 주소에서 키를 제거한다. 완료된 씬을 건너뛰어 미완료 씬을 이어서 연다.

인증 전 원본 프레임/판독 데이터 접근을 계속 차단한다. 팀 코드를 아는 사람은 작업자를 선택할 수 있으며, 개인별 접근 통제 대신 판독 기록 구분을 제공한다. 코드는 서버 설정에만 두고 URL·저장소에 넣지 않는다. 이전 내부 키와 판독 JSON은 유지했다. 저장이 끝나기 전에는 작업자 전환을 막는다.

## 사용자가 완료한 첫 씬 확인

`mlb-777438-2-top` 41개 프레임이 실제 서버에 저장돼 있다. R01 revision 63과 후속 R02 revision 124를 읽었다. 두 작업자 모두 마지막 접촉 177 / 첫 분리 178로 지정했다.

- R01: 과거 164번의 공 좌표가 남아 릴리스 전 분류와 충돌했다. 원본 164번은 준비 동작이고 해당 표시는 몸통 부근이다. 다른 판독으로 덮어쓰지 않았다.
- R02: 릴리스 이전에도 공 좌표를 표시했다. 좌표 삭제나 임의 음성 라벨 변환 없이 현재 자유 비행 라벨 정의와의 충돌로 표시했다. 단순히 모든 프레임에 값이 있다고 완료 처리하지 않았다.
- 완성률과 좌표 정확도는 별개다. 이번 확인은 저장·입력 일관성 점검이며 전 프레임의 독립 정답 정확도를 계산한 것이 아니다.

## 검증

- Node 단위/HTTP 테스트 9개, Python 테스트 2개 통과.
- 코드 없는 로그인/잘못된 코드/비정상 작업자 거부, 올바른 작업자 인증, 로그인 자체가 판독을 만들지 않음, 인증 전 판독 차단, 큰 요청·과도한 접속 제한을 검사했다.
- 41개 표시가 모두 있어도 첫 분리 전의 공 표시를 특정 프레임으로 안내하는지 검사했다.
- 실제 R01 기록의 별도 QA 복사본에서 공통 로그인 → 164번 확인 표시 → 해당 점의 분류 수정 → 씬 완료 전환 → 다음 씬 이동 → 새로고침 복원 → R02 전환을 브라우저로 시험했다. QA의 수정은 실제 기록에 반영하지 않았다.
