# 릴리스 표식에 따른 공 추적 검증

## 판정

기존 앱, 릴리스 상한까지 기존 출력을 가린 대조군, 릴리스 뒤에 후보 경로를 다시 연결하는 실험 모델을 비교했다. 새 방식은 실제 검출점으로 경로를 구성하고, 경쟁 경로의 점수가 비슷한 프레임은 표시를 보류한다. 실험은 2D 좌표까지 진행했다. 독립 투구의 출처별 사전 기준을 통과하지 못했다.

| 비교 자료 | 보이는 기준점 | 기존 앱 일치 | 출력만 가림 | 새 연결 | 명확한 공 부재에서 오검출, 기존→새 |
|---|---:|---:|---:|---:|---:|
| MLB 미사용 3경기 4구 | 20 | 19 | 16 | 16 | 0→0 / 17 |
| 야외 아카데미 미사용 클립 #1 | 7 | 4 | 4 | 6 | 1→0 / 14 |
| OBP Prime 다른 카메라, 같은 투구 | 24 | 24 | 24 | 0 | 0→0 / 5 |
| 기존 개발 자료 8개 영상 | 118 | 33 | 27 | 31 | 8→0 / 37 |

일치는 가로 960px 환산 8px 이내다. 손 근처 좌표가 포함된 과거 판독도 주 비교 분모에 그대로 뒀다. 별도로 릴리스 상한 이후만 보면 MLB 16/16→16/16이며 같은 16프레임의 좌표도 동일하다. MLB의 전체 일치 감소 3개는 릴리스 상한 전후의 표시 보류로 설명된다. 아카데미는 상한 뒤 4/6→6/6으로 개선됐다. 아카데미 두 방식이 공통으로 반환한 4개 중심의 평균 차이는 각각 0.90px였다. 새 방식이 맞힌 2개가 추가됐다.

## 릴리스 표식과 실패 원인

| 자료 | 한 프레임 일찍 | 원래 표식 | 한 프레임 늦게 |
|---|---:|---:|---:|
| 미사용 MLB | 19/20 | 16/20 | 8/20 |
| 미사용 아카데미 | 7/7 | 6/7 | 5/7 |
| Prime 카메라 22 | 0/24 | 0/24 | 23/24 |

- 시드 종료를 릴리스 상한 뒤 3프레임에서 5프레임으로 늘렸을 때 위 세 자료의 결과는 모두 원래 표식 조건과 같았다. 표시 시각은 유지하면서 구간 안부터 추적하니 MLB는 4/20, 아카데미 6/7, Prime 0/24였다. 모두 사후 탐색으로 구분했다.
- Prime 카메라 22는 기준 위치 주변 후보가 상한 이후 24/24에 있었다. 기존 앱은 이를 모두 따라갔지만, 새 모델은 경쟁 경로 6프레임을 보류하고 1프레임에서 기준과 약 121.2px 다른 점을 선택했다. 새 경로를 선택하는 규칙이 확인된 실패 지점이다.
- Rapsodo 개발 두 구에서 상한 뒤 63개 중 42개에 위치가 맞는 후보가 있었으나 새 연결은 0개를 맞혔다. 아카데미 개발 #3은 7/7에서 후보가 있었으나 새 연결이 모두 다른 점을 선택했다. 두 곳에서 후보 목록만 늘려서는 문제를 해결하기 어렵다.
- 다음 실험은 릴리스 뒤 새 경로를 시작하기 전에 기존의 일관된 경로도 비교 후보로 보존하는 것이다. 후보 궤적의 후속 관측 지지를 보고, 유효한 기존 경로를 교체할 근거가 있을 때만 바꾼다. 서로 다른 투수와 카메라가 섞인 별도 원본에서 검증할 때까지 위 결과를 앱 기본값으로 적용하지 않는다.

## 출처와 재현

- 미사용 MLB는 경기 ID 778343, 776503, 778480의 원본 4개다. 별도 검토자가 기존 공 중심 좌표와 결과를 보기 전에 릴리스 구간과 대략적인 검출 범위를 정했다. 원본 영상과 기존 수동 공 좌표의 해시를 연결했다.
- 야외 아카데미 #1은 기존 #3과 다른 던지기 영상이다. 원본의 필요한 바이트 범위를 받아 처음 145프레임을 재인코딩 없이 추출했고 비교 구간의 픽셀과 시각 일치를 확인했다. 일반적인 전력 투구인지, 다른 카메라나 세션인지는 확인되지 않았다. 라이선스가 명시되지 않아 원본 및 겹친 결과를 로컬에 뒀다. [Academy 데이터](https://huggingface.co/datasets/dyland222/international_amateur_baseball_catcher_video_dataset)
- 카메라 전이는 같은 Prime 투구의 카메라 19에서 22로 바꾼 별도 검사다. 화면에 새겨진 번호와 검토에 사용하는 0기반 디코드 번호는 구분한다. [OBP 원본 프로젝트](https://github.com/drivelineresearch/openbiomechanics)

    python -m experiments.release_conditioned_ball.study manifest.json comparison-diagnostic.json
    python -m experiments.release_conditioned_ball.render manifest.json comparison-diagnostic.json overlay.mp4 --font <한글 폰트>
    python -m unittest -q experiments.shared_ball_tracking.test_study experiments.release_conditioned_ball.test_study
    node --test apps/pitch-capture/core/*.test.mjs experiments/release_conditioned_ball/track.test.mjs

Python 5개, Node 20개 테스트를 통과했다. 원영상 겹침 영상 150프레임을 모두 디코드하고 대표 프레임을 확인했다. 원본과 결과 JSON은 로컬에 보존했다.
