# 씬별 제출 수정 검증

## 문제와 변경

기존 제출은 전체 배정 씬의 판독과 입력 일관성 검사 완료를 요구했다. 한 씬을 모두 판독해도 다른 씬이 미시작이거나 접촉/분리 표시가 충돌하면 제출할 수 없었다.

주 버튼을 씬별 제출로 변경했다. 모든 프레임을 판독한 씬은 접수하되 불일치는 `needs_review`로 보존한다. 원래 좌표와 릴리스 값을 자동 수정하지 않는다. 연구용 결과의 기존 엄격한 입력 검사는 유지한다. 제출 후 수정은 별도 상태로 표시하며 재제출 시 접수 이력을 추가한다.

## 재현 및 검증

- 수정 전 새 회귀 테스트: 접수 기록이 없어서 실패(`scene submission must return a receipt`).
- 수정 후 `node --test tools/pitch_labeler/*.test.cjs`: 14개 통과, 실패 0개.
- `python -m unittest discover -s tools/pitch_labeler -p "test_*.py"`: 2개 통과, 실패 0개.
- 실제 기록 복사본을 사용하는 별도 로컬 QA 서버에서 첫 씬 41/41, 나머지 씬 미판독 상태로 제출했다. 새 접수 1개와 이력 1개가 파일에 저장됐으며 `needs_review`, 전체 `submittedAt: null`이었다. 제출 전후 판독 사전은 동일했다.
- 브라우저 새로고침 후 1/4개 씬 접수와 첫 씬의 접수 완료·검토 필요 표시를 확인했다. 다음 미제출 씬을 열었고 접수된 씬으로 돌아와도 접수 상태를 유지했다.
- 실제 작업자 원본 기록에는 QA 제출을 하지 않았다. 프레임과 기록, 키, 화면 캡처는 Git 밖에 보관한다.

자동 테스트는 미완료 씬 제출 거부, 다른 씬 보존, 수정 후 재제출, 접수 이력, 이전 revision 충돌, 잘못된 씬 ID, 자동 저장과 제출 순서, 실패 후 재시도, 응답 유실 후 재접속을 검사한다. 이 검증은 저장·접수 기능 검증이며 영상 판독이나 구속 정확도 검증이 아니다.
